# План размещения и индексации без платной рекламы

Состояние на 2026-09-06: внутренний Telegram-кластер Stage 20 опубликован и валиден, но свежий внешний поиск пока не возвращает `site:alexgtup.github.io`. Поэтому ближайшая задача — не создавать новые похожие посадочные, а добиться повторного обхода основных URL и дать поисковику несколько реальных внешних точек входа.

## Приоритет 0 — индексация

1. В Google Search Console проверить URL:
   - https://alexgtup.github.io/
   - https://alexgtup.github.io/telegram-bots/
   - https://alexgtup.github.io/cases/fin-planner/
2. Для URL, которые Google ещё не проиндексировал, использовать URL Inspection → Request indexing.
3. Проверить, что sitemap `https://alexgtup.github.io/sitemap.xml` читается без ошибок и содержит 56 индексируемых URL.
4. В Яндекс Вебмастере отправить на переобход главную, `/telegram-bots/` и `/cases/fin-planner/`.
5. Не менять title/H1 этих страниц снова до появления новых данных об обходе/показах.

## Неделя 1 — внешний Telegram authority

1. GitHub profile: вручную создать публичный репозиторий `Alexgtup/Alexgtup` и использовать подготовленный `GITHUB_PROFILE_README.md` как README. Через текущий GitHub-коннектор создание нового репозитория недоступно.
2. Обновить описание профиля Freelance.ru текстом из `external-publications/04-freelance-profile.txt`. В приоритете ссылка именно на `/telegram-bots/` и реальный кейс `/cases/fin-planner/`, а не только на главную.
3. Опубликовать один самостоятельный материал про Фин Планер. Основная ссылка внутри материала — на кейс; дополнительная естественная ссылка — на `/telegram-bots/`.

## Неделя 2 — второй независимый источник

1. Опубликовать технический материал «Telegram-бот как продукт: как проектировать сценарий, а не меню из кнопок» из `external-publications/03-habr-telegram-product.md`, адаптировав начало под требования выбранной площадки.
2. Не копировать текст первой публикации. Поисковику нужны независимые страницы, а не синдикация одного и того же текста.
3. Разместить короткий кейс-пост в 1–2 релевантных сообществах только там, где разрешена самопрезентация/кейсы.

## Неделя 3 — расширение доказательств

1. Если появился новый реальный Telegram-проект — оформить его отдельным кейсом и связать с `/telegram-bots/`.
2. Если нового Telegram-кейса нет, не создавать фиктивный. Следующий внешний материал можно сделать по CRM/API, сохраняя общий entity-сигнал Alexuys.
3. Проверить, какие внешние страницы уже попали в индекс и по каким запросам начал показываться бренд/домен.

## Контроль через 7–14 дней

Смотреть отдельно по `/telegram-bots/`:

- impressions;
- clicks;
- CTR;
- average position;
- реальные queries;
- indexing status;
- referring pages / источники переходов, если доступны.

Решение о следующем изменении страницы принимать только после этих данных. Если есть показы, но слабый CTR — работать со сниппетом. Если показов почти нет при индексированном URL — усиливать authority/cases. Если URL не индексирован — сначала решать crawl/indexing, а не переписывать текст.

## Правило

Один коммерческий интент = одна основная страница. Для «разработка Telegram-бота / создание Telegram-бота / заказать Telegram-бота» основной URL — `https://alexgtup.github.io/telegram-bots/`. Гайды и кейсы поддерживают эту страницу, а не конкурируют с ней.
